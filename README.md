# 🛍️ Interactive Store Catalog — Full Stack (Next.js + Supabase)

تطبيق كتالوج منتجات لمحل، عربي **Full Stack**: واجهة عملاء RTL + لوحة تحكم + باك إند حقيقي يحفظ
الكتالوج والطلبات في قاعدة بيانات Supabase (Postgres).

## المميزات

- كتالوج RTL سريع ومتجاوب: بحث، أقسام، سلة، وإرسال الطلب على واتساب برقم طلب حقيقي.
- **دخول لوحة التحكم حصرياً بـ Supabase Auth (إيميل + باسورد)** من الحساب الموجود في
  `Authentication → Users`. مفيش أي دخول محلي أو رقم سري في المشروع.
- كل API خاص بالأدمن بيتحقق من **Supabase access token على السيرفر** — أي طلب من غير توكن صالح بيرجع `401`.
- رفع صور المنتجات إلى Cloudinary مع الاسم والوصف والسعر والوزن والمورد.
- سعر قديم وجديد مع حساب نسبة الخصم تلقائياً وعداد اختياري يُدخل باليوم والشهر والسنة.
- قسم «الأكثر مبيعاً» يُرتّب تلقائياً من بيانات الطلبات الفعلية، بدون ترتيب يدوي.
- واجهة وإعدادات عربية فقط، مع مفضلة محفوظة على جهاز الزائر وإمكانية إعادة آخر طلب بضغطة واحدة.
- تبويب عروض حي، وفرز بالسعر أو الأحدث، مع إيقاف الخصم تلقائياً بعد تاريخ انتهائه.
- Hero carousel قابل للإدارة من لوحة التحكم، مع إيقاف تلقائي عند تمرير المؤشر وخيارات تنقّل واضحة.
- صفحة QR محلية قابلة للتنزيل والطباعة (`/qr`) ومنيو/كتالوج للطباعة أو الحفظ PDF (`/menu`) — بدون خدمة QR خارجية.
- اختيار من لوحة التحكم بين العرض التفصيلي الحالي أو شبكة من 3 منتجات، مع تصفية كل منتجات المورد بالضغط على اسمه.
- تسجيل الطلب قبل فتح رسالة واتساب، مع سجل للطلبات داخل لوحة التحكم.
- **تبويب «الطلبات»**: كل الطلبات المسجّلة مع فلاتر (حالة/نوع/فترة) وبحث بالاسم أو الموبايل أو رقم
  الطلب، تحديث الحالة (جديد → مؤكد → تم التسليم / ملغي)، وتصدير CSV متوافق مع الإكسل العربي.
- **تنبيه صوتي ووميض في عنوان التاب** مع أي طلب جديد على أي تبويب مفتوح في اللوحة، مع عداد أحمر
  على تبويب الطلبات — تحديث لحظي عبر Realtime مع فحص دوري احتياطي.
- **فتح وقفل أوتوماتيك**: جدول مواعيد أسبوعي (بتوقيت القاهرة) بيشغّل ويقفل المحل لوحده، بيدعم
  الفترات اللي بتعدي نص الليل، والسيرفر بيرفض أي طلب وقت القفل، مع إظهار موعد الفتح القادم للعميل.
- **مناطق توصيل برسوم مختلفة**: لكل منطقة رسومها وحدها الأدنى، والعميل يختار منطقته في السلة —
  والرسوم بتتحسب على السيرفر ضد التلاعب، مع متغيّر `{zone}` في قالب الواتساب.
- **طرق دفع**: كاش / فودافون كاش / انستاباي… العميل يختار في السلة وتوصل في رسالة الواتساب
  ومتغيّر `{payment}`، وتظهر في فوتر الموقع.
- **تحليلات مبيعات** في «نظرة عامة»: إيراد اليوم/الأسبوع/الشهر، متوسط قيمة الطلب، رسم بياني
  لإيراد آخر ١٤ يوم، وأعلى المنتجات بالإيراد (الطلبات الملغية مستثناة).
- إشعارات Web Push اختيارية للعروض والمنتجات الجديدة، مع زر واضح لإلغاء الاشتراك.
- نسخ احتياطي يدوي ويومي مجدول مع الاحتفاظ بآخر 30 نسخة واسترجاع من لوحة التحكم.
- حفظ لحظي مركزي: تعديل الأدمن يظهر لكل العملاء على كل الأجهزة، ولافتة واضحة عند انقطاع الإنترنت.

## الباك إند

| المسار | الوصف | الصلاحيات |
| --- | --- | --- |
| `GET /api/menu` | قراءة الكتالوج | عام |
| `PUT /api/menu` | حفظ الكتالوج | أدمن (Supabase token) |
| `POST /api/orders` | تسجيل الطلب قبل فتح رسالة واتساب | عام |
| `GET /api/admin/overview` | سجل الطلبات + حالة التخزين | أدمن (Supabase token) |
| `PATCH /api/admin/orders` | تحديث حالة طلب (جديد/مؤكد/تم التسليم/ملغي) | أدمن (Supabase token) |
| `GET /api/admin/session` | التحقق من جلسة الأدمن على السيرفر | أدمن (Supabase token) |

التحقق من التوكن بيتم في `lib/server-auth.ts` بمخاطبة `SUPABASE_URL/auth/v1/user`،
والبيانات بتتحفظ عن طريق `lib/server-database.ts`.

## قاعدة البيانات

نفّذ [`supabase/schema.sql`](supabase/schema.sql) مرة واحدة في Supabase → SQL Editor.

> **ترقية من نسخة قديمة؟** نفّذ الملف تاني بنفس الطريقة — كل الأوامر آمنة للتكرار
> (`create or replace` / `if not exists`)، وده ضروري لتفعيل تحديث حالة الطلبات
> (`update_order_status`) ومناطق التوصيل داخل `place_order`.

الملف بينشئ:

- `catalog_data` — الكتالوج (قراءة عامة، كتابة للأدمن).
- `orders` — الطلبات (قراءة للأدمن).
- `catalog_backups` — آخر 30 نسخة كاملة من الكتالوج؛ الوصول لها من API السيرفر فقط.
- `push_subscriptions` — اشتراكات Web Push؛ لا يمكن قراءتها مباشرة من المتصفح.
- `place_order(payload jsonb)` — دالة `SECURITY DEFINER` تتحقق من المنتجات والأسعار ومنطقة التوصيل وتسجّل الطلب بحالة «جديد» بدون أي متابعة للمخزون.
- `update_order_status(order_id, status)` — دالة `SECURITY DEFINER` للأدمن فقط تحدّث حالة الطلب.
- تفعيل **Supabase Realtime** على الجداول (`alter publication supabase_realtime add table ...`)
  عشان التحديث اللحظي يوصل فوراً لكل الأجهزة عبر WebSocket.

> **بداية ببيانات فارغة:** بيانات البداية لا تحتوي على أي أقسام أو منتجات — أدخل أقسامك ومنتجاتك من لوحة التحكم.

> **نقل مشروع Menyu القديم:** من «البيانات» ارفع ملف JSON القديم كما هو. النظام يتعرّف على نسخة Firebase تلقائياً وينقل الأقسام والمنتجات والصور والـ variants والخصومات والموردين (بأسمائهم بدل `supplierId`) وصور الـ Hero. راجع النتيجة في المعاينة قبل نشرها.

> **التحديث اللحظي:** تعديلات الكتالوج والطلبات الجديدة بتوصل فوراً عن طريق Supabase Realtime، مع فحص دوري احتياطي لو الاتصال انقطع.

> لحد ما تنفّذ الملف، الموقع بيشتغل على ملف مؤقت للتطوير، وتظهر لك لافتة حمراء في لوحة
> التحكم تطلب تنفيذ الـ schema.

## متغيرات البيئة

```env
NEXT_PUBLIC_SUPABASE_URL=https://YOUR-PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=sb_publishable_...
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME=your-cloud-name
NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET=store-catalog
NEXT_PUBLIC_SITE_URL=https://your-store.example

# Server-only: لا تضعها في متغير يبدأ بـ NEXT_PUBLIC_
SUPABASE_SERVICE_ROLE_KEY=sb_secret_...
NEXT_PUBLIC_VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
VAPID_SUBJECT=mailto:owner@your-store.example
CRON_SECRET=a-long-random-secret
```

القيم متظبطة في **Vercel → Project Settings → Environment Variables**.
واجهات الكتالوج والطلبات تستخدم مفتاح `anon` العام فقط. أما `SUPABASE_SERVICE_ROLE_KEY` فهو اختياري ومستخدم **على السيرفر فقط** لإنشاء النسخ المجدولة وحفظ/إرسال Web Push؛ لا تضعه أبداً في متغير يبدأ بـ `NEXT_PUBLIC_` أو في أي كود متصفح.

### إعداد النسخ التلقائي وإشعارات Push

1. بعد تنفيذ `supabase/schema.sql`، أضف `SUPABASE_SERVICE_ROLE_KEY` في بيئة Vercel فقط. هذا المفتاح لا يصل للمتصفح ويُستخدم للـ backups والـ push فقط.
2. أنشئ مفاتيح VAPID عبر `npx web-push generate-vapid-keys`، ثم أضف `NEXT_PUBLIC_VAPID_PUBLIC_KEY` و`VAPID_PRIVATE_KEY` و`VAPID_SUBJECT`.
3. أضف `CRON_SECRET` عشوائياً وطويلاً في Vercel. ملف `vercel.json` يستدعي `/api/cron/backup` يومياً الساعة 02:15 UTC، ويحتفظ الموقع بآخر 30 نسخة. يمكن إنشاء نسخة أو استرجاع نسخة من تبويب «البيانات» أيضاً.
4. أضف `NEXT_PUBLIC_SITE_URL` كرابط الإنتاج الحقيقي كي تعمل الـ canonical links و`/sitemap.xml` بشكل صحيح.

> زر الجرس يظهر فقط على متصفح يدعم Web Push وبعد ضبط VAPID. الإشعار لا يُرسل إلا عند إضافة منتج أو تشغيل/تغيير عرض؛ حفظ أي تعديل عادي لا يزعج العملاء.

### إعداد Cloudinary للصور

1. من Cloudinary افتح **Settings → Upload → Upload presets**.
2. أنشئ preset من نوع **Unsigned** ويفضّل تقييده بملفات الصور وبحد أقصى 5MB.
3. أضف اسم الـ cloud والـ preset في متغيرات البيئة الموضحة فوق.
4. أعد نشر المشروع. بعدها رفع اللوجو وصورة الغلاف وصور المنتجات من لوحة التحكم
   يرفعها مباشرةً إلى Cloudinary ويحفظ رابط `https` فقط بدل تخزين الصورة داخل بيانات الكتالوج.

> اسم الـ cloud والـ unsigned preset قيم عامة مصممة للاستخدام من المتصفح؛ لا تضف
> `API Secret` أو `API Key` إلى متغيرات تبدأ بـ `NEXT_PUBLIC_`.

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local   # وحط قيم مشروعك في Supabase
npm run dev
```

- الموقع: `http://localhost:3000`
- لوحة التحكم: `http://localhost:3000/admin` — بالإيميل والباسورد بتوع يوزر Supabase.
